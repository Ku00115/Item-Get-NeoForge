# Item Get! v1.0.4 External Trigger Guide

This document records the v1.0.4 workflow for external triggers, commands, and API access.

## Goal

v1.0.4 should let modpack authors and other mods use Item Get! as a general reminder and handbook system, even when the player did not actually obtain an item.

Primary use cases:

- A scene interaction block opens a lore/tutorial reminder.
- A command block, datapack function, KubeJS script, or CraftTweaker script triggers a reminder.
- Another mod triggers an Item Get! entry through Java API.
- The reminder can still be recorded in the handbook so the player can read it again later.
- Existing item, entity, world, player, advancement, observation, and dimension triggers continue to work.

## New Trigger Type

Use this trigger type for reminders that are not detected automatically:

```text
Manual Trigger
```

Stored type:

```text
MANUAL
```

Trigger data:

```json
{
  "manual": "modpack:first_magic_terminal"
}
```

The `manual` value is an author-defined trigger id. Use namespaced ids:

```text
modpack:first_magic_terminal
modpack:create_depot_intro
story:chapter_1_start
quest:opened_spellbook
```

## Editor Workflow

Pack author flow:

1. Open the Item Get! manager.
2. Create a new reminder.
3. Set trigger type to `Manual Trigger`.
4. Enter a manual trigger id, such as `modpack:first_magic_terminal`.
5. Edit title, subtitle, description, icon, sound, display style, and Ponder links.
6. Save.
7. Trigger it through command, script, datapack, or API.

Editor field:

```text
Manual trigger id
```

The field should be a direct text input. No registry browser is needed because these ids are pack-authored.

## Commands

### Trigger And Record

```mcfunction
/itemget trigger <targets> <rule_id>
```

Shows the reminder for each target, marks it as triggered, and records it in the handbook. It follows normal one-time behavior. If the player has already triggered this reminder revision, nothing happens.

Example:

```mcfunction
/itemget trigger @p modpack_first_magic_terminal
```

### Force Trigger

```mcfunction
/itemget trigger <targets> <rule_id> force
```

Shows the reminder even if the player has already triggered it. Handbook history should not duplicate the same rule revision.

Example:

```mcfunction
/itemget trigger @a modpack_first_magic_terminal force
```

### Show Only

```mcfunction
/itemget show <targets> <rule_id>
```

Only displays the reminder. It does not mark progress and does not record it in the handbook. Use this for testing or temporary messages.

Example:

```mcfunction
/itemget show @p modpack_first_magic_terminal
```

### Fire Manual Trigger Id

```mcfunction
/itemget fire <targets> <manual_trigger_id>
```

Finds enabled `Manual Trigger` rules whose manual id matches the given value. Shows and records matching reminders with normal one-time behavior.

Example:

```mcfunction
/itemget fire @p modpack:first_magic_terminal
```

### Force Manual Trigger Id

```mcfunction
/itemget fire <targets> <manual_trigger_id> force
```

Forces matching manual-trigger reminders to display.

Example:

```mcfunction
/itemget fire @p modpack:first_magic_terminal force
```

## Existing Commands To Keep

These commands should remain available:

```mcfunction
/itemget reset <targets>
/itemget unlock <targets> all
/itemget unlock <targets> <rule_id>
/itemget handbook
/itemget manager
```

`unlock` should continue to record entries in the handbook without displaying a popup.

## Java API

Add the same public package and class name in Forge and NeoForge:

```java
package com.kuzhi.itemget.api;

public final class ItemGetApi {
}
```

Recommended methods:

```java
public static boolean trigger(ServerPlayer player, String ruleId);
public static boolean trigger(ServerPlayer player, String ruleId, boolean force);
public static boolean show(ServerPlayer player, String ruleId);
public static boolean unlock(ServerPlayer player, String ruleId);
public static boolean isUnlocked(ServerPlayer player, String ruleId);
public static boolean reset(ServerPlayer player);
public static int fireExternalTrigger(ServerPlayer player, String triggerId);
public static int fireExternalTrigger(ServerPlayer player, String triggerId, boolean force);
```

Method behavior:

- `trigger`: show a rule by rule id, mark progress, and record in handbook.
- `trigger(..., true)`: show even if already triggered.
- `show`: show a rule by rule id without progress or handbook record.
- `unlock`: record a rule in the handbook without showing it.
- `isUnlocked`: check whether the current rule revision is already unlocked for the player.
- `reset`: clear Item Get! progress for one player.
- `fireExternalTrigger`: trigger every enabled `Manual Trigger` rule matching a manual trigger id.

## Java API Example

```java
import com.kuzhi.itemget.api.ItemGetApi;
import net.minecraft.server.level.ServerPlayer;

public static void onTerminalUsed(ServerPlayer player) {
    ItemGetApi.fireExternalTrigger(player, "modpack:first_magic_terminal");
}
```

## Command Block Example

Create a manual reminder with:

```text
Manual trigger id: modpack:first_magic_terminal
```

Then use this command:

```mcfunction
/itemget fire @p modpack:first_magic_terminal
```

This is useful for adventure maps, scene blocks, datapack functions, and simple modpack interactions.

## Datapack Function Example

```mcfunction
execute as @a[tag=opened_magic_terminal] run itemget fire @s modpack:first_magic_terminal
tag @a[tag=opened_magic_terminal] remove opened_magic_terminal
```

## KubeJS Example

Exact KubeJS syntax may depend on Minecraft and KubeJS version, but the intended command workflow is:

```js
ServerEvents.blockRightClicked(event => {
  if (event.block.id == 'modpack:magic_terminal') {
    event.server.runCommandSilent(`itemget fire ${event.player.username} modpack:first_magic_terminal`)
  }
})
```

When a Java API call is easier in a given script environment, use `ItemGetApi.fireExternalTrigger(player, triggerId)` instead.

## Handbook Behavior

For `trigger` and `fire`:

- If the rule has not been triggered for this player and revision, show the reminder.
- Mark the rule as shown for this player.
- Add it to handbook history.
- Do not duplicate the same rule revision in history.

For `force`:

- Show the reminder even if it was already triggered.
- Keep handbook history deduplicated.

For `show`:

- Show the reminder only.
- Do not mark progress.
- Do not write handbook history.

For `unlock`:

- Mark progress and add handbook history.
- Do not show a popup.

## Implementation Notes

- Keep the real progress write path shared between commands and API.
- Do not make API methods client-only.
- Do not expose internal network packets as the public API.
- Do not require other mods to construct `ReminderRule` directly for common use cases.
- Keep API methods tolerant: return `false` or `0` when the rule or trigger id is missing instead of crashing.
- Commands should use rule-id suggestions where possible.
- Manual trigger ids should be free-form namespaced strings, not registry entries.
- Forge and NeoForge should expose the same API package and method names.

## Optional Authoring Skill

A separate Codex skill can help pack authors generate Item Get! configuration directly:

```text
$item-get-config-author
```

Expected use:

- Read existing Item Get! config.
- Add or update reminder rules.
- Generate stable rule ids.
- Use translation-key-ready title, subtitle, and description values.
- Pick reasonable icons, sounds, display style, and trigger types.
- Avoid duplicate ids.
- Explain what each generated rule does.

This skill does not need to be part of the mod JAR.
